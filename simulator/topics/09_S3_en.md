## Glossary: the services you will encounter in this document

- **S3 (Simple Storage Service)** — AWS's object/file storage. Think of it as an infinite hard drive in the cloud where you can put any file: images, videos, documents, backups. Files are organized in "buckets" (containers). S3 is extremely durable (11 nines = you practically never lose a file) and redundant by default. You can also host a static website directly from S3.

- **Bucket** — the container where you put your files in S3. The bucket name must be **globally unique** across all of AWS. Inside a bucket you can create "folders" (which are actually just prefixes in the file name).

- **Storage Class** — the "service tier" for your objects in S3. The more frequent the access, the more storage costs but the less retrieval costs. The rarer the access, the less storage costs but the more it costs (and the longer it takes) to retrieve the data. Like choosing between a warehouse in the city center (expensive but immediate access) and a depot in the suburbs (cheap but it takes hours to get there).

- **S3 Glacier** — the "archive" version of S3. Costs very little to store data, but when you want it back you have to wait from minutes to hours. Perfect for data you must keep by law but almost never access. Like putting boxes in a self-storage unit: cheap, but it takes time to go get them.

- **Lifecycle Policy** — an automatic rule that moves your objects between storage classes over time. Example: after 30 days move to Standard-IA, after 90 days to Glacier, after 7 years delete. Like an automatic system that moves documents from the current archive to the historical archive and then to the shredder.

- **Versioning** — S3 can keep all previous versions of a file. If someone overwrites or deletes a file by mistake, you can recover the previous version. Like "Ctrl+Z" but for files in the cloud.

- **Presigned URL** — a temporary link that allows anyone to download (or upload) a file from your private bucket, without needing AWS credentials. It has an expiration. Like giving someone a temporary pass to enter your office.

- **Transfer Acceleration** — uses CloudFront edge locations to speed up uploads to S3 from remote locations. Like shipping a package through an express courier that has warehouses around the world.

## What is Amazon S3

PACKT describes S3 as *"uno dei primi e più critici servizi AWS. Lanciato nel 2006, fornisce una piattaforma robusta per salvare e recuperare qualsiasi quantità di dati."*

The Dojo adds architectural details: *"S3 è un servizio di object storage. È un servizio web che non è confinato a un singolo dispositivo di storage. Non risiede nel tuo VPC o in nessuna Availability Zone. Il traffico tra la tua istanza EC2 e un bucket S3 passa di default attraverso l'Internet pubblico, non dentro il tuo VPC."*

### Fundamental Characteristics

- **Scalability**: unlimited storage, max 5 TB per object (PACKT)
- **Durability**: 99.999999999% (11 nines) — *"Se avessi 1 milione di oggetti in S3, potresti aspettarti di passare 10 milioni di anni prima di perderne uno"* (PACKT). The Dojo explains: data is automatically replicated across all data centers in the Region
- **Availability**: 99.99% over a year (Dojo)
- **Bucket names**: globally unique — *"Nessun'altra persona sul pianeta può creare un bucket con lo stesso nome"* (Dojo)
- **Flat structure**: S3 doesn't have a true file hierarchy. "Folders" are just prefixes in the object key (Dojo)
- **No POSIX**: S3 doesn't support concurrent access like a file system. For that you need EFS or FSx for Lustre (Dojo)

## Security Controls in S3 (from PACKT and Dojo)

PACKT warns: *"Internet è pieno di storie di clienti che lasciano bucket S3 aperti al mondo. Di default, tutti i bucket S3 sono creati senza accesso pubblico."*

### Access Control Methods

| Method | Description |
|---|---|
| **Bucket Policies** | Bucket-level JSON policies — who can do what (PACKT, Dojo) |
| **ACLs** | Granular control on individual objects — generally replaced by IAM (PACKT) |
| **IAM** | Users, groups, roles with specific S3 permissions (PACKT) |
| **VPC Endpoints** | Private access from VPC without going through the internet (Dojo) |

### Public vs Private Access (from Dojo)

The Dojo explains how to access S3 privately from the VPC:
- **Interface Endpoint**: ENI with private IP, allows access from on-premises and cross-region. Paid
- **Gateway Endpoint**: entry in the route table, doesn't allow access from on-premises or cross-region. **Free**

> **Dojo note**: *"Una volta creato l'endpoint, assicurati di aggiornare la bucket policy con una condizione che permette agli utenti di accedere al bucket S3 quando la richiesta proviene dal VPC endpoint."*

### Encryption (from PACKT)

S3 offers both server-side encryption (SSE) and client-side encryption:
- **SSE-S3**: key managed by S3 (default)
- **SSE-KMS**: key managed in KMS (CMK)
- **SSE-C**: key provided by the customer

## Versioning (from PACKT and Dojo)

PACKT describes versioning as a feature that *"mantiene multiple varianti di un oggetto nello stesso bucket, progettata per proteggere i dati da sovrascrittura o cancellazione."*

The Dojo adds: *"Di default, il versioning è disabilitato. Una volta abilitato, non può essere disabilitato, ma può essere sospeso. Il versioning mette deletion markers sulle versioni degli oggetti per marcarli come rimossi, invece di cancellarli permanentemente."*

Related features (from PACKT):
- **MFA Delete**: requires MFA to delete object versions
- **Object Lock**: prevents modification or deletion. **Governance mode** (some users can modify) or **Compliance mode** (no one can modify)

> **PACKT note**: *"Usare il versioning può avere costi significativi perché le vecchie versioni potrebbero non essere cancellate e i requisiti di storage possono crescere rapidamente."*

## Storage Classes (from PACKT and Kimiko)

### The Classes (from PACKT)

| Class | Use | Retrieval | Durability |
|---|---|---|---|
| **S3 Standard** | Frequently accessed data (default) | Immediate | 11 nines |
| **S3 Standard-IA** | Infrequently accessed data but with quick access when needed. Lower storage cost, retrieval fee | Immediate | 11 nines |
| **S3 One Zone-IA** | Like Standard-IA but in a single AZ. Lower costs, reduced availability | Immediate | Reduced (data lost if AZ destroyed — Dojo) |
| **S3 Glacier** | Long-term archival. Retrieval from minutes to hours | Minutes-hours | 11 nines |
| **S3 Glacier Deep Archive** | Very long-term archival. Retrieval up to 12 hours | Up to 12 hours | 11 nines |
| **S3 Outposts** | On-premises S3 storage for latency-sensitive applications | Local | N/A |

The Dojo adds: *"S3 Standard-IA costa meno di S3 Standard in termini di prezzo storage, fornendo la stessa alta durabilità, throughput e bassa latenza. S3 One Zone-IA ha il 20% di costo in meno rispetto a Standard-IA."*

### Intelligent Tiering (from PACKT)

PACKT describes 4 automatic tiers:
1. **Frequent access**: data accessed more than once every 30 days. High storage, low retrieval, milliseconds
2. **Infrequent access**: less regular access but nearly instant. Lower storage, higher retrieval
3. **Archive access**: rarely accessed data. Retrieval 3-5 hours
4. **Deep archive access**: data not expected to be accessed except in exceptional circumstances. Retrieval 12 hours

### Note from Kimiko on Storage Classes

Kimiko warns: *"Ogni volta che distolgo lo sguardo per un momento e poi torno ad AWS, vedo che sono state create ulteriori storage classes S3. Non farti prendere dal panico. Dai un'occhiata a queste aree che tendono a cambiare frequentemente prima dell'esame. Ma ricorda che spesso una certificazione sarà un po' indietro rispetto agli ultimi avanzamenti. Le classi classiche e più frequentemente usate sarebbero certamente quelle su cui farebbero domande."*

## Lifecycle Policies (from PACKT and Dojo)

PACKT provides a practical example for a bank that must retain data for 5 years:

```
Day 0:       S3 Standard (frequent access, high storage cost)
Day 30:      → S3 Standard-IA (less frequent access)
Day 60:      → S3 Glacier (archival)
Day 365:     → S3 Glacier Deep Archive (deep archival)
5 years:     → Deletion
```

The Dojo specifies the lifecycle policy parameters:
- Whether to apply to all objects or only to a group with a specific prefix
- The number of days after creation before the action is applied
- Lifecycle policies can also **expire versioned objects and permanently delete them**

## Important S3 Features (from Dojo)

| Feature | Description |
|---|---|
| **Multipart Upload** | For objects > 100MB. Splits the file into parts, parallel upload, retry for failed parts, pause/resume |
| **S3 Transfer Acceleration** | Uses CloudFront edge locations to optimize long-distance transfers. You only pay if there's improvement |
| **Static Web Hosting** | Bucket as a static website. Doesn't support HTTPS — needs CloudFront. Bucket name must exactly match the domain name |
| **Cross-Region Replication** | Automatic replication of objects to another Region. Requires versioning enabled on both buckets (PACKT) |
| **Object Ownership** | For external users uploading objects to your bucket — you can automatically assume ownership |

## Kimiko's Hands-on Challenge: S3

Kimiko proposes a practical challenge:

1. **Create a bucket** named `[lastname]-09876` (globally unique)
2. **Create a lifecycle policy** that moves objects to Glacier after 120 days
3. **Create three folders**: data, data1, data2
4. **Upload a file** to the data2 folder
5. **Delete everything** when you're done

In the walkthrough, Kimiko shows practical details:
- You can copy settings from an existing bucket as a template
- If you don't change options/permissions, you can skip directly to "Create" without going through all screens
- The lifecycle policy warns that it might increase costs, especially with many small objects
- When you click on a file's Object URL, you get "Access Denied" because you're accessing as an unauthenticated identity from the internet — for it to work you'd need to open read permissions to the entire world

## S3 Glacier — Retrieval Options (from Dojo)

The Dojo provides specific retrieval time details that are fundamental for the exam:

### S3 Glacier Flexible Retrieval

| Option | Time | Note |
|---|---|---|
| **Expedited** | 1-5 minutes | Only if AWS has enough retrieval capacity |
| **Standard** | 3-5 hours | Default |
| **Bulk** | 5-12 hours | Cheapest |

### S3 Glacier Deep Archive

| Option | Time |
|---|---|
| **Standard** | Within 12 hours |
| **Bulk** | Within 48 hours |

> **Dojo note**: *"Puoi fare transizione da S3 Glacier a S3 Glacier Deep Archive ma NON il contrario."*

### Minimum Charges (from Dojo)

The Dojo provides a critical table for understanding hidden costs:

| Storage Tier | Min Capacity per Object | Min Storage Duration | Retrieval Fee |
|---|---|---|---|
| S3 Standard | None | None | None |
| S3 Intelligent Tiering | None | None | None |
| S3 Infrequent Access | **128 KB** | **30 days** | Per GB |
| S3 One Zone-IA | **128 KB** | **30 days** | Per GB |
| S3 Glacier Instant Retrieval | **40 KB** | **90 days** | Per GB |
| S3 Glacier Flexible Retrieval | **40 KB** | **90 days** | Per GB |
| S3 Glacier Deep Archive | **40 KB** | **180 days** | Per GB |

> **Dojo note**: *"Se un oggetto è più piccolo del minimum capacity, viene fatturato come se fosse della dimensione minima. Se cancelli un oggetto prima del minimum storage duration, vieni fatturato come se fosse stato salvato per l'intera durata minima."*

Example: if you store a 40 KB object in S3 IA (min 128 KB) for 15 days (min 30 days), you pay as if it were 128 KB for 30 days.

## Presigned URLs (from Dojo)

The Dojo explains: *"Di default, tutti i bucket e oggetti S3 sono privati. I proprietari possono condividere oggetti con altri utenti usando presigned URLs. Una presigned URL concede permessi time-limited per scaricare o caricare oggetti."*

To create a presigned URL you specify:
- Your security credentials
- The bucket name and object key
- The HTTP method (GET for download)
- Expiration date and time

> A presigned URL can be used many times, as long as it hasn't expired.

## S3 Encryption — Detail (from Dojo)

### Server-Side Encryption (SSE)

| Method | Key | Audit Trail | Note |
|---|---|---|---|
| **SSE-S3** | S3 manages the keys (AES-256). Each object encrypted with a unique key | No | Default, simplest |
| **SSE-KMS** | Key managed in KMS (AWS managed or customer managed) | **Yes** — CloudTrail logs when the CMK is used and by whom | Granular control, audit |
| **SSE-C** | You provide the key in every request. S3 handles encryption/decryption | No | You manage the keys |

### Client-Side Encryption (CSE)

Data is encrypted **before** uploading to S3. The key can be:
- A CMK stored in KMS
- A master key that you store in your application

## Choosing the Right Storage Service (from PACKT Ch.14)

PACKT Ch.14 provides guidelines for the exam:

| Requirement | Service | Why |
|---|---|---|
| **Low-latency, high-performance block storage** | **EBS** | For databases and transactional systems |
| **Shared file system across multiple instances** | **EFS** | Supports NFS, scales automatically |
| **Massive scalability and durability** | **S3** | Content distribution, data lakes, backup |
| **Low-cost, durable storage** | **S3** with appropriate storage classes | Lifecycle policies to optimize costs |

> **Exam tip (PACKT Ch.14)**: *"Read the exam question carefully to determine any specific requirements for the storage. Does the question require the lowest cost solution? Or does it require high performance and low latency?"*

## Typical Exam Scenarios

### Scenario 1: Data archival for compliance
**Question**: Data must be retained for 7 years, rarely accessed.

**Answer**: **S3 with lifecycle policy** — Standard → Standard-IA after 30 days → Glacier after 60 days → Deep Archive after 1 year → Delete after 7 years (PACKT example).

### Scenario 2: Private S3 access from VPC
**Question**: EC2 instances in a private subnet need to access S3 without the internet.

**Answer**: **Gateway Endpoint** for S3 — free, entry in the route table (Dojo).

### Scenario 3: Large file upload
**Question**: You need to upload 5GB files to S3.

**Answer**: **Multipart Upload** — recommended for objects > 100MB (Dojo).

### Scenario 4: Static website with HTTPS
**Question**: You want to host a static site on S3 with HTTPS.

**Answer**: S3 Static Web Hosting + **CloudFront** for HTTPS (Dojo: *"S3 website endpoints do not support HTTPS. You will need to add a CloudFront"*).

### Scenario 5: Non-critical data at lowest cost
**Question**: Non-critical, reconstructible log data to be stored at the lowest cost.

**Answer**: **S3 One Zone-IA** — 20% less than Standard-IA, but data lost if AZ destroyed (Dojo).

## Quick Recap for the Exam

- **S3**: object storage, 11 nines durability, 99.99% availability, globally unique bucket names (PACKT, Dojo)
- **Not a file system**: flat structure, no POSIX, no concurrent access — for that use EFS/FSx (Dojo)
- **S3 traffic goes through the internet** by default — use VPC Endpoint for private access (Dojo)
- **Gateway Endpoint**: free, S3/DynamoDB only. **Interface Endpoint**: paid, cross-region, on-premises (Dojo)
- **Storage Classes**: Standard → Standard-IA → One Zone-IA → Glacier → Deep Archive (decreasing cost, increasing retrieval) (PACKT)
- **Intelligent Tiering**: 4 automatic tiers based on access frequency (PACKT)
- **Lifecycle Policies**: automatic transition between classes + scheduled deletion (PACKT, Dojo)
- **Versioning**: once enabled cannot be disabled, only suspended. Deletion markers, not actual deletion (Dojo)
- **Object Lock**: Governance mode (override possible) vs Compliance mode (no one can modify) (PACKT)
- **Multipart Upload**: for objects > 100MB, parallel upload (Dojo)
- **Transfer Acceleration**: uses CloudFront edge locations, you only pay if it improves (Dojo)
- **Static Web Hosting**: no native HTTPS, needs CloudFront. Bucket name = domain name (Dojo)
- **Replication**: requires versioning on source and destination. For SSE-KMS, configure cross-account key access (PACKT)
- **EBS for low-latency, EFS for shared file system, S3 for massive scalability** (PACKT Ch.14)
- **Glacier retrieval**: Expedited (1-5 min), Standard (3-5h), Bulk (5-12h). Deep Archive: Standard (12h), Bulk (48h) (Dojo)
- **Minimum charges**: IA min 128KB/30 days, Glacier min 40KB/90 days, Deep Archive min 40KB/180 days (Dojo)
- **Presigned URLs**: time-limited access to private objects, reusable until expiration (Dojo)
- **SSE-KMS**: the only one with audit trail in CloudTrail (Dojo)
- **You cannot transition** from Glacier Deep Archive to Glacier (only the reverse) (Dojo)
